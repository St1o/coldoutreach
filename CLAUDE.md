# coldoutreach: карта проекта

Читайте эту карту первой и открывайте только файлы под задачу. Цифры в таблицах: примерный размер в токенах.

## Что это
1. Клиент и сайт выписок ЕГРЮЛ по ИНН (`egrul_inn_search.py`, `app.py`, `index.html`).
2. Таблица новых компаний `/leads`: название, ФИО директора, почта, ОКВЭД (код, название), источник почты (ЕГРЮЛ или контакты Checko).
3. Рассылка: тексты писем пишут агенты Cowork (файлы `.md` лежат вне репозитория), `compose.py` собирает письма, `mailer.py` отправляет через mail.ru с одного или нескольких ящиков (`MAILRU_USER`, `MAILRU_USER_2`, …).

Поток рассылки: `leads_<дата>.csv` + файлы агентов `.md` → `compose.py` → `letters_<этап>.csv` → `mailer.py` → mail.ru. Группу письма определяет карта ОКВЭД от агента (`okved-map.md`: решение по смыслу для каждого кода, в том числе «не писать»), иначе таблица классов из файла сегмента (первые два знака кода), иначе запасная группа 12. Коды без решения агента `compose.py` выписывает в `okved_to_classify.md` (папка данных; только коды и названия видов деятельности и сокращения форм организаций): этот файл передают агенту. Форма организации (ООО, МБУ, ПК…) берётся из начала названия; пока агент не решил иначе (раздел `## Формы` в `okved-map.md`), пишем только ООО. У запасной группы и групп без своего текста может быть свой шаблон письма целиком (заголовки «Письмо 1. Запасной шаблон» и т. п. в файле писем). Этап 1 можно пройти кнопкой «Отправить» на `/leads` (`send_service.py`): таблица сама пишется в папку данных `OUTREACH_DATA`, в таблице выгрузки три колонки «Первое письмо», «Дожим», «Закрывающее» (да или нет, по журналам `letters_N.sent.json`; `leads.table_rows`, `leads.refresh_table`), строки с ушедшим письмом на странице залиты жёлтым до колонки последнего ушедшего письма. Страница показывает таблицу только за выбранную дату (`LeadsJob.status(day)`, запрос `?date=`); дата идёт и в скачивание, и в «Отправить». Журнал `letters_<этап>.sent.json` (статус, время, тема, группа, источник адреса). Этапы 2 (дожим) и 3 (закрывающее) строятся по журналам. Отправка по уже собранной базе без нового запроса к Checko (сайт может работать как обычно): `compose.py <папка данных> --limit N --preview` берёт все сохранённые таблицы `leads_<дата>.csv` (старые даты первыми) и только тех, кому ещё ничего не отправляли; так дирижёр отвечает на «давай сейчас отправим сообщения». **Несколько ящиков и прогрев** (`mailing/mailboxes.py`): ящики 1..5 из `local.env` (суффикс `_2`, `_3`, …), письма идут одним процессом по очереди (1, 2, 1, 2…) с общей случайной паузой 30-75 с (`--pause`, `--jitter`). У каждого ящика квота на сегодня: в день первого письма 7, дальше на 3 больше в день (7, 10, 13, …), не больше жёсткого предела недели прогрева (дни 1-7: 15, дни 8-14: 30, с дня 15: 40; константы `WARMUP_WEEK_CAPS`, `WARMUP_CAP_LATER`, от `/mail` не зависят), не больше потолка «Лимит отправки» (страница `/mail`, 40 по умолчанию, не выше 50; он может только понизить предел недели) и не больше потолка за 24 часа; дата первого письма: `settings.json` (страница `/mail`), иначе `local.env` (`MAIL_FIRST_MESSAGE`, `MAIL_FIRST_MESSAGE_2`, …), иначе самое раннее письмо ящика в журнале, иначе день 1 наступит с первым письмом. Журнал помнит ящик каждого письма (`mailbox`; записи без поля = ящик 1); дожим и закрывающее идут с ящика первого письма. Выбор ящиков: `--mailboxes N` (первые N; по умолчанию все подключённые), `--mailbox 2` (только они); на странице `/leads` поле «Со скольки почт отправить» и список «Или только с одной почты». Квоты: `python mailer.py "<папка данных>" --status` (по строке на ящик, адреса скрыты). Порядок работы для владельца: `LOCAL.md`, раздел «Рассылка».

## Как пользоваться рассылкой (напоминать владельцу по его просьбе)
Когда владелец спрашивает, как пользоваться рассылкой, в каком порядке всё делается, когда решает агент («напомни порядок», «как это работает»), перескажите эти шаги простыми словами, как для первокурсника, и добавьте, что из этого уже сделано и что дальше. Порядок утверждён владельцем (2026-10-11):

1. Вы говорите дирижёру «хочу рассылку», он запускает сайт.
2. Вы вставляете текст с Checko, сайт собирает таблицу. Агентов тут нет.
3. Вы говорите «отправить сообщения». Дирижёр запускает проверку (или вы нажимаете «Отправить», окно покажет то же самое). Программа смотрит на каждую компанию: какая форма и какой вид деятельности. Что знает по решениям агента, применяет. Что не знает, записывает в файл `okved_to_classify.md`. Письма пока не уходят.
4. Здесь решает агент. Дирижёр отдаёт файл агенту, тот возвращает решения. Это делается один раз на каждый новый код или форму, дальше всё запоминается.
5. Программа собирает письма заново по решениям агента, вы видите окно «Что будет отправлено», подтверждаете, и письма уходят.

Пояснение для владельца: программа как сортировщик на складе со справочником. Чего в справочнике нет, она кладёт на стол «вопросы эксперту», эксперт (агент) решает и вписывает в справочник. Агент сам не включается, его запускает дирижёр на шаге 4; если шаг пропустить, программа работает по старым правилам (пишет только ООО, группа по первым двум знакам кода) и предупреждает строкой в окне. Пока владелец не утвердил запасной шаблон письма, в группы без своего текста письма не отправляются (галочку «запасной вариант» не ставить).

## Тесты
Папка `tests/`, по файлу на модуль (`tests/test_mailer.py`, `tests/test_compose.py`, ...). Читайте только тест того модуля, который меняете. Запуск всего: `python -m unittest discover -q` (около 300 тестов, 35 секунд). Тесты не должны трогать настоящие `local.env` и `settings.json` (передавайте временные пути).

## Правила
- **У владельца одна рабочая ветка: `claude/happy-meitner-e6i3m3`** (она же главная на GitHub); имена веток сессий он больше не отслеживает (решение владельца). Коммитьте и пушьте сами, без отдельной просьбы (запрет владелец отменил 2026-10-12). Порядок: правка и push в ветку сессии; полный прогон тестов (`python -m unittest discover -q`); `git fetch`, и если главная ушла вперёд, влить её в свою ветку и снова прогнать тесты; затем слить ветку сессии в `claude/happy-meitner-e6i3m3` (`git merge --no-ff`) и сделать в неё обычный push (без `--force`). Тесты упали или конфликт не решается однозначно: в главную не пушить, сказать владельцу. Pull request не создавать, пока не попросят.
- **Правки ушли в git: всегда говорите владельцу, что проект в PyCharm нужно обновить, и давайте краткие шаги.** Ветка владельца всегда `claude/happy-meitner-e6i3m3`: называйте её и хэш последнего коммита (владелец сверяет его со строкой «git: … коммит» в `check_version`). Шаги: 1) остановить сайт (красный квадрат в окне Run); 2) **Git → Fetch**; 3) **Git → Update Project** (Ctrl+T) на ветке `claude/happy-meitner-e6i3m3`; если владелец стоит на другой ветке, один раз: внизу справа нажать на название ветки → **Remote Branches** → `origin/claude/happy-meitner-e6i3m3` → **Checkout**; 4) если PyCharm скажет про изменённые файлы, выбрать *Smart Checkout*, не *Force*; 5) запустить `run_local` заново. Если правка меняла `requirements.txt`, добавить в Terminal `pip install -r requirements.txt`. `local.env` и папка данных в git не лежат, при смене ветки они остаются на месте. Если правка касалась файлов агентов (их нет в git), скажите, что именно передать дирижёру.
- `mailer.py`, `compose.py` и `mailing/` работают на одной стандартной библиотеке (без pip): их копируют на другие машины.
- Корень проекта хранит `local.env` (пароли ящиков, ссылка на форму, пути к файлам агентов) и `settings.json` (лимит с сайта); оба вне git. Пути к ним задаёт `mailing/config.py`.
- Репозиторий публичный: адреса, ФИО, пароли, журналы и тексты агентов в него не попадают (см. `.gitignore`). В сообщениях программ адреса при необходимости скрываются (`--mask-addresses`, `--background`).
- Письма не подставляют ФИО и названия компаний; нет ссылки на форму (или подписи, если в шаблоне есть `{{подпись}}`) - письма не собираются.
- Интерфейс для владельца: команды `python compose.py ...`, `python mailer.py ...`, `python run_local.py` и тексты в `LOCAL.md` не менять без причины: на них опираются инструкции агентов.
- Сообщения программ и документы на русском. Windows и PyCharm у владельца: проверяйте код, зависящий от ОС (процессы, пути).
