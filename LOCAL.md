# Запуск на своём компьютере через PyCharm

Так страница пробного письма (`/mail`) работает у вас, а не на Render: на бесплатном плане Render закрыты исходящие порты почты, а с компьютера они открыты.

Пароли и адрес хранятся только в файле `local.env` на вашем компьютере. В git он не попадает (он в `.gitignore`). Репозиторий публичный, поэтому **не пишите пароли в файлы проекта и не отправляйте их в чат**.

Нужен Python 3.10 или новее (проверено на 3.10 и 3.13). Инструкция написана для PyCharm Community 2021.2.

## Один раз

1. **Проект.** Верхнее меню **VCS → Get from Version Control…**
   - *URL:* `https://github.com/St1o/coldoutreach.git`
   - *Directory:* новая папка, например `E:\Codes\coldoutreach` (не папка уже открытого пустого проекта).
   - Нажмите **Clone**. Если PyCharm пишет, что Git не найден, нажмите *Download and Install*. Входить в GitHub не нужно: репозиторий публичный.
   - На вопрос «Open in…» выберите *This Window* (или *New Window*).
2. **Ветка.** В правом нижнем углу окна (строка состояния) нажмите на название ветки → **Remote Branches → origin/claude/local-pycharm → Checkout**. Если такой ветки нет в списке, сначала **VCS → Git → Fetch**. Проверка: в панели Project слева должны появиться файлы `run_local.py` и `LOCAL.md`.
3. **Интерпретатор.** В правом нижнем углу должно быть написано `Python 3.10 (…)`. Если там `<No interpreter>`, нажмите на надпись → **Add Interpreter…** → *Virtualenv Environment* → *New environment* → *Base interpreter*: Python 3.10 → OK. (Можно выбрать и уже существующий `Python 3.10 (1venv)` из списка.)
4. **Пакеты.** Внизу вкладка **Terminal**, выполните:
   ```
   pip install -r requirements.txt
   ```
   Дождитесь строки «Successfully installed …». В начале строки терминала должно быть `(venv)` или `(1venv)`: значит, пакеты ставятся в окружение проекта. Если вместо этого вверху файла появилась жёлтая полоса «Package requirements are not satisfied», можно нажать в ней *Install requirements*.
5. **Пароль для почты.** В настройках почты на mail.ru создайте «пароль для внешних приложений» (раздел «Безопасность» → «Пароли для внешних приложений»; название пункта в меню может отличаться). Старый пароль, который уже попадал в чат, удалите там же.
6. **Первый запуск.** В панели Project правой кнопкой на `run_local.py` → **Run 'run_local'**. Внизу откроется окно Run, программа напишет, что создала файл `local.env`, и остановится. Файл появится в панели Project (если не видно: правой кнопкой на папке проекта → *Reload from Disk*). Откройте его двойным щелчком (если PyCharm предложит поставить плагин для `.env`, откажитесь) и впишите две строки без пробелов и кавычек:
   ```
   MAILRU_USER=ваш_адрес@mail.ru
   MAILRU_APP_PASSWORD=пароль_для_внешних_приложений
   ```
   Сохраните: **Ctrl+S**.

## Каждый раз

Запустите `run_local` ещё раз (после первого запуска зелёная кнопка ▶ вверху справа запускает его сама). Откроется браузер на странице `/leads`: таблица новых компаний и кнопка «Отправить». Пароль вводить не надо ни при каких условиях: пароль страниц `/leads` и `/mail` берётся из `local.env` (строка `LEADS_PASSWORD=…` или `LEADS_TOKEN=…`; если обеих нет, при первом запуске программа сама дописывает `LEADS_TOKEN`; пароль защищает страницы от посторонних, если сайт стоит не только у вас). Не путайте его с ключом Checko: тот лежит в отдельной строке `CHECKO_API_KEY=…`, а сайт, запущенный у вас на компьютере, сам отдаёт его своим страницам. Поэтому и вкладка, открытая заново, и адрес `http://127.0.0.1:8000/leads`, набранный вручную, открываются сразу. Пароль в `local.env` можно заменить своим, но только из латинских букв и цифр, не короче 12 знаков: с русскими буквами он не подойдёт, и программа создаст другой на этот запуск. Если всё же видите форму пароля, сайт запущен старой версией программы: остановите его (красный квадрат в PyCharm) и запустите `run_local` заново. Со страницы `/leads` ссылка ведёт на `/mail`: пробное письмо и лимит отправки. Остановить сайт: красный квадрат в PyCharm.

Папка данных рассылки (таблицы, письма, журналы) по умолчанию `outreach-data` рядом с папкой проекта, например `E:\Codes\outreach-data`; другую можно задать строкой `OUTREACH_DATA=…` в `local.env`. Название папки и пути печатаются при запуске.

## Рассылка: тексты пишут агенты, письма собираете и отправляете вы

Три места, которые не смешиваем:
- **Папка агентов** (`Автоматизация бизнеса`): тексты писем и сегмент. Адресов, ФИО и паролей там нет.
- **Папка данных**, например `E:\Codes\outreach-data`: вне папки агентов и вне git. Здесь таблица `leads_<дата>.csv`, стоп-лист, ответы опроса, собранные письма и журналы отправки. Сайт создаёт её сам (по умолчанию `outreach-data` рядом с папкой проекта, или путь из `OUTREACH_DATA` в `local.env`).
- **Проект `coldoutreach`**: программы. Пароль от ящика только в его `local.env`.

Агенты пишут шаблоны с подстановками и блоки боли по группам видов деятельности. `compose.py` подставляет значения (группа по ОКВЭД, ссылка на опрос, подпись) и собирает письма; `mailer.py` их отправляет. ФИО и названия компаний в письма не попадают.

### Один раз

1. В `local.env` допишите (по образцу в `local.env.example`): `CHECKO_API_KEY` (ключ API Checko из личного кабинета: без него выгрузка на `/leads` не работает), `SURVEY_LINK` (ссылка на **форму** опроса `docs.google.com/forms/…/viewform`, не на таблицу с ответами; откройте её в окне без входа в Google, форма должна открываться), `MAIL_SIGNATURE` (подпись под письмом: нужна, только если в шаблонах агентов есть `{{подпись}}`; нет такой подстановки, ничего вписывать не надо), `OUTREACH_LETTERS` и `OUTREACH_SEGMENT` (пути к файлам писем и сегмента в папке агентов). Пока подписи или ссылки нет, письма не собираются. Лимит писем в сутки задаётся не здесь, а на странице `/mail` сайта.
2. В папке данных создайте пустой `stoplist.txt`. В нём по строке: адрес (`name@mail.ru`) или целый домен (`@registrar.ru`). Строки с `#` игнорируются.

### Каждая партия: кнопкой на сайте

1. На странице `/leads` вставьте текст Checko, укажите дату и нажмите «Запустить». Таблица `leads_<дата>.csv` сама сохраняется в папку данных: скачивать и переносить её не нужно. После перезапуска сайта страница показывает таблицу последней выгрузки.
2. Ниже таблицы блок «Отправка писем»: впишите, сколько писем отправить (для нового ящика 10–15 в сутки), нажмите «Отправить». Откроется окно проверки: сколько писем соберётся, по каким группам, сколько адресов пропущено и почему, и пример письма (без адреса и ФИО). Нажмите «Отправить N писем» в окне, и отправка пойдёт в фоне с паузой 30 секунд между письмами; страницу можно закрыть. Дневной лимит, журнал, стоп-лист и «одна отправка на папку» работают те же, что в командной строке.
3. В таблице колонка «Письмо» и бледные строки: у кого письмо уже ушло, у того строка бледная с временем отправки; «адрес не принят» красным. Тем, кому письмо уже отправлено, оно повторно не уходит. Если письма для какой-то группы агенты ещё не написали, их по умолчанию не собирают; галочка под числом писем разрешает отправить таким компаниям запасной вариант текста.
4. Дожим и закрывающее письмо, стоп-лист, ответы опроса: командной строкой, пункты 5–7 ниже.

### Каждая партия: командной строкой

Команды вводите на вкладке **Terminal** в PyCharm (в начале строки `(venv)`). Те же шаги, что делает кнопка на сайте.

1. **Таблица.** Возьмите `leads_<дата>.csv` из папки данных (на странице `/leads` её же можно скачать). В ней должны быть колонки «ОКВЭД (код)» и «Источник почты»: старые выгрузки без них не подойдут, выгрузите заново. Письма пойдут только на адреса с источником «ЕГРЮЛ» (адреса из контактов Checko пропускаются).
2. **Сборка и просмотр.**
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --limit 150 --preview
   ```
   Программа напишет, сколько писем собрано, по каким группам, сколько адресов пропущено и почему, и покажет по одному письму на группу (без адресов). Группы, для которых агенты ещё не написали блок боли, не собираются: программа об этом скажет. Тему можно выбрать ключом `--subject 2`. В папке данных появится `letters_1.csv`.
3. **Пробные письма себе** (проверка доставки на своих ящиках).
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --test-to ваш@mail.ru,ваш@gmail.com
   python mailer.py "E:\Codes\outreach-data\letters_test.csv" --send
   ```
   Каждый адрес получит письмо одной из групп. Посмотрите в ящике, как оно выглядит, не в спаме ли, открывается ли ссылка на опрос без входа в Google. Повторить пробу тем же адресам можно после удаления `letters_test.sent.json`.
4. **Первая партия.**
   ```
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --mask-addresses
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --send --limit 5
   ```
   Первая команда только проверяет. Между письмами пауза 30 секунд. За сутки с одного почтового ящика не уходит больше писем, чем задано в блоке «Лимит отправки» на странице `/mail` сайта (запустите `run_local`; по умолчанию 40; новый ящик «прогревают»: в первые дни поставьте 10-15 и поднимайте понемногу). Новое значение действует со следующего запуска отправки. Остальные письма партии уйдут при следующем запуске, после того как пройдут сутки. В каждое письмо добавляется заголовок List-Unsubscribe.

   **Отправка в фоне.** С ключом `--background` программа запускает отправку отдельным процессом и сразу возвращает управление, ждать окончания не нужно:
   ```
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --send --limit 40 --background
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --status
   ```
   Вторая команда показывает, сколько отправлено и осталось, идёт ли отправка и последние строки журнала `mailer.log` (адреса в нём скрыты: `n***@mail.ru`). В одной папке одновременно идёт только одна отправка (файл `mailer.lock`): вторую программа не запустит. Продолжить партию на следующий день можно той же командой.
5. **Ящик ответов и отписки.** Читайте ящик каждый день. Отказ, просьба удалить данные, жалоба: адрес сразу в `stoplist.txt` (программа пропустит его при следующем запуске), партию на паузу, дальше решаете вы.
6. **Дожим (через 3 рабочих дня) и закрывающее (через 7 дней).** Раз в день скачайте ответы опроса из Google Таблицы файлом CSV и положите в папку данных как `responses.csv` (программа ищет в нём все адреса почты). Затем:
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --stage 2 --preview
   python mailer.py "E:\Codes\outreach-data\letters_2.csv" --send --limit 5
   ```
   Для этапа 2 берутся адреса, которым первое письмо отправлено три рабочих дня назад и раньше; для этапа 3 (`--stage 3`) те, кому ушёл дожим и с первого письма прошла неделя. Те, кто есть в `responses.csv` или в стоп-листе, не получают ничего. Тема и группа берутся из журнала отправки, письмо всегда на тот же адрес и с той же темой. Больше трёх писем на адрес не уйдёт. Кто заполнил опрос с другого адреса или указал только телефон или Telegram, получит дожим: этот риск принят.
7. **Итоги партии** в `batches.md`: сколько отправлено (число в журнале `letters_1.sent.json`, строки со статусом `sent`), недоставлено, ответов, отписок.

### Если программа остановилась

`mailer.py` печатает причину; код выхода:

| Код | Что случилось | Что делать |
|---|---|---|
| 0 | Готово | Посмотреть, сколько отправлено |
| 1 | Ошибка в таблице или не заданы `MAILRU_USER` / `MAILRU_APP_PASSWORD` | Исправить таблицу или `local.env` |
| 2 | mail.ru не принял логин или пароль | Нужен «пароль для внешних приложений», а не обычный. Не повторять |
| 3 | mail.ru отказал или ограничил отправку (например `451 Ratelimit exceeded`) | Остановиться. Продолжать не раньше чем через несколько часов, партию уменьшить |
| 5 | Несколько временных отказов подряд | Остановиться, повторить позже |

Повторный запуск с той же таблицей безопасен: кому письмо уже ушло, тому оно повторно не отправляется. Журналы `letters_*.sent.json` не удаляйте: по ним считаются дожим, закрывающее и дневной лимит. Нельзя: уменьшать `--pause` ниже 30 секунд, перезапускать сразу после кода 2, 3 или 5, пробовать тем же письмом с другого ящика. Если сервер ограничил отправку, это сигнал сбавить темп, а не обойти.

Страница `/mail` остаётся проверкой соединения с mail.ru и местом, где задаётся лимит в сутки: пример письма на ней устроен иначе, чем письма рассылки.

## Если что-то не так

- **С включённым VPN Checko не отвечает, а без VPN работает.** Checko (как многие российские сервисы) закрывает соединения с зарубежных адресов, а при VPN запросы идут с адреса VPN: ни Python, ни `curl` тут не виноваты. Программа обходит это сама: если обычный запрос оборвался, она отправляет запросы к Checko напрямую, через настоящую сетевую карту (Ethernet или Wi-Fi), мимо VPN; остальной интернет по-прежнему идёт через VPN. Права администратора не нужны, работает только в Windows. Не помогает, если в VPN включена блокировка трафика вне VPN («kill switch»): выключите её или добавьте в исключения VPN (раздельное туннелирование) программу, которой запущен сайт. Нужны оба пути (python.exe из `venv` запускает базовый), `check_checko.py` печатает их в конце, обычно это `E:\Codes\coldoutreach\vikmax\1venv\Scripts\python.exe` и python.exe базовой установки Python. Либо исключите адреса `api.checko.ru` и `checko.ru`. Проверить, обходит ли программа VPN, можно запуском `check_checko.py` при включённом VPN: строка «Запрос к API (в обход VPN…)» должна быть «ок», а в списке «Сетевые карты с выходом в интернет» одна из карт помечена «через неё идёт обход VPN» (если там пусто или написана причина сбоя, значит, мимо VPN из программы выйти нельзя: используйте исключения в самом VPN). Письма (`mailer.py`) идут на `smtp.mail.ru` тоже с адреса VPN, а mail.ru смотрит, откуда входят в ящик: если письма не уходят или ящик просит подтвердить вход, для рассылки исключите python.exe из VPN или выключайте VPN.
- **На странице `/leads` в журнале «защищённое соединение с api.checko.ru оборвано (SSL)», «прокси не пропустил запрос» или «нет соединения»,** а выгрузка пишет «Данные не получены». Это не пароль и не ключ (с неверным ключом пришёл бы «HTTP 401» или «403»): компьютер не может установить соединение с Checko. Программа сама пробует обойти (без системного прокси, потом с TLS 1.2, потом через системную программу curl: в Windows 10 она встроена и шифрует средствами самой Windows, а не Python), но если и это не помогло, запустите `check_checko.py` (правой кнопкой на файле → *Run 'check_checko'*): по шагам проверит адрес (и сверит его с публичным DNS), соединение, шифрование, запрос из Python и через curl, обычные сайты и сам ключ (один настоящий запрос из 100 бесплатных в сутки) и простыми словами напишет, где обрыв. В тексте «No such file or directory» среди ошибок файл ни при чём: так Python иногда сообщает, что сервер закрыл соединение посреди установки шифрования. Чаще всего мешает VPN или прокси с не российским адресом либо антивирус с проверкой защищённых соединений (Kaspersky, ESET, Dr.Web): отключите VPN, а в антивирусе отключите проверку HTTPS или добавьте `api.checko.ru` в исключения.

- **«Не заполнено: …»** — впишите значения в `local.env`, сохраните (Ctrl+S), запустите снова.
- **«No module named requests»** (или другой модуль) — пакеты не установились в то окружение, которым запускается проект: повторите шаг 4 и проверьте, что в правом нижнем углу выбран тот же интерпретатор, что в терминале.
- **«Не удалось проверить защищённое соединение… (SSLCertVerificationError)»** — Python не смог проверить сертификат `smtp.mail.ru`. Это происходит до ввода пароля, к паролю отношения не имеет. Сначала обновите проект (**Git → Update Project**) и запустите снова: программа доверяет и хранилищу Windows, и стандартному набору `certifi`. Если ошибка осталась, запустите `check_cert.py` (правой кнопкой → *Run 'check_cert'*) и пришлите его вывод: там видно, кем выдан сертификат. Отключать проверку сертификатов нельзя: тогда пароль могут перехватить. Если понадобится добавить корневой сертификат вручную, впишите в `local.env` строку `MAILRU_CA_FILE=путь\к\файлу.pem`.
- **«mail.ru не принял логин или пароль»** — нужен именно пароль для внешних приложений, а `MAILRU_USER` должен быть полным адресом.
- **«Порт занят»** — в *Run → Edit Configurations… → Parameters* впишите `--port 8001`.
- **Другая ошибка в красной строке под кнопкой** — пришлите её текст.
