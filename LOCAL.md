# Запуск на своём компьютере через PyCharm

Так страница пробного письма (`/mail`) работает у вас, а не на Render: на бесплатном плане Render закрыты исходящие порты почты, а с компьютера они открыты.

Пароли и адрес хранятся только в файле `local.env` на вашем компьютере. В git он не попадает (он в `.gitignore`). Репозиторий публичный, поэтому **не пишите пароли в файлы проекта и не отправляйте их в чат**.

Нужен Python 3.10 или новее (проверено на 3.10 и 3.13). Инструкция написана для PyCharm Community 2021.2.

## Один раз

1. **Проект.** Верхнее меню **VCS → Get from Version Control…**
   - *URL:* `https://github.com/St1o/coldoutreach.git`
   - *Directory:* новая папка, например `E:\Codes\coldoutreach` (не папка уже открытого пустого проекта).
   - Нажмите **Clone**. Если PyCharm пишет, что Git не найден, нажмите *Download and Install*. Входить в GitHub не нужно: репозиторий публичный.
   - На вопрос «Open in…» выберите *This Window* (или *New Window*).
2. **Ветка.** В правом нижнем углу окна (строка состояния) нажмите на название ветки → **Remote Branches → origin/claude/local-pycharm → Checkout**. Если такой ветки нет в списке, сначала **VCS → Git → Fetch**. Проверка: в панели Project слева должны появиться файлы `run_local.py` и `LOCAL.md`.
3. **Интерпретатор.** В правом нижнем углу должно быть написано `Python 3.10 (…)`. Если там `<No interpreter>`, нажмите на надпись → **Add Interpreter…** → *Virtualenv Environment* → *New environment* → *Base interpreter*: Python 3.10 → OK. (Можно выбрать и уже существующий `Python 3.10 (1venv)` из списка.)
4. **Пакеты.** Внизу вкладка **Terminal**, выполните:
   ```
   pip install -r requirements.txt
   ```
   Дождитесь строки «Successfully installed …». В начале строки терминала должно быть `(venv)` или `(1venv)`: значит, пакеты ставятся в окружение проекта. Если вместо этого вверху файла появилась жёлтая полоса «Package requirements are not satisfied», можно нажать в ней *Install requirements*.
5. **Пароль для почты.** В настройках почты на mail.ru создайте «пароль для внешних приложений» (раздел «Безопасность» → «Пароли для внешних приложений»; название пункта в меню может отличаться). Старый пароль, который уже попадал в чат, удалите там же. Для второго ящика создайте такой же пароль в его настройках (раздел «Безопасность» → «Пароли для внешних приложений», с доступом к почте по IMAP/SMTP); подключение второго ящика описано ниже, в разделе «Несколько ящиков и прогрев».
6. **Первый запуск.** В панели Project правой кнопкой на `run_local.py` → **Run 'run_local'**. Внизу откроется окно Run, программа напишет, что создала файл `local.env`, и остановится. Файл появится в панели Project (если не видно: правой кнопкой на папке проекта → *Reload from Disk*). Откройте его двойным щелчком (если PyCharm предложит поставить плагин для `.env`, откажитесь) и впишите две строки без пробелов и кавычек:
   ```
   MAILRU_USER=ваш_адрес@mail.ru
   MAILRU_APP_PASSWORD=пароль_для_внешних_приложений
   ```
   Сохраните: **Ctrl+S**.

## Каждый раз

Запустите `run_local` ещё раз (после первого запуска зелёная кнопка ▶ вверху справа запускает его сама). Откроется браузер на странице `/leads`: таблица новых компаний и кнопка «Отправить». Пароль вводить не надо ни при каких условиях: пароль страниц `/leads` и `/mail` берётся из `local.env` (строка `LEADS_PASSWORD=…` или `LEADS_TOKEN=…`; если обеих нет, при первом запуске программа сама дописывает `LEADS_TOKEN`; пароль защищает страницы от посторонних, если сайт стоит не только у вас). Не путайте его с ключом Checko: тот лежит в отдельной строке `CHECKO_API_KEY=…`, а сайт, запущенный у вас на компьютере, сам отдаёт его своим страницам. Поэтому и вкладка, открытая заново, и адрес `http://127.0.0.1:8000/leads`, набранный вручную, открываются сразу. Пароль в `local.env` можно заменить своим, но только из латинских букв и цифр, не короче 12 знаков: с русскими буквами он не подойдёт, и программа создаст другой на этот запуск. Если всё же видите форму пароля, сайт запущен старой версией программы: остановите его (красный квадрат в PyCharm) и запустите `run_local` заново. Со страницы `/leads` ссылка ведёт на `/mail`: пробное письмо и лимит отправки. Остановить сайт: красный квадрат в PyCharm.

Папка данных рассылки (таблицы, письма, журналы) по умолчанию `outreach-data` рядом с папкой проекта, например `E:\Codes\outreach-data`; другую можно задать строкой `OUTREACH_DATA=…` в `local.env`. Название папки и пути печатаются при запуске.

## Рассылка: тексты пишут агенты, письма собираете и отправляете вы

Три места, которые не смешиваем:
- **Папка агентов** (`Автоматизация бизнеса`): тексты писем и сегмент. Адресов, ФИО и паролей там нет.
- **Папка данных**, например `E:\Codes\outreach-data`: вне папки агентов и вне git. Здесь таблица `leads_<дата>.csv`, стоп-лист, ответы опроса, собранные письма и журналы отправки. Сайт создаёт её сам (по умолчанию `outreach-data` рядом с папкой проекта, или путь из `OUTREACH_DATA` в `local.env`).
- **Проект `coldoutreach`**: программы. Пароль от ящика только в его `local.env`.

Агенты пишут шаблоны с подстановками и блоки боли по группам видов деятельности. `compose.py` подставляет значения (группа по ОКВЭД, ссылка на опрос, подпись) и собирает письма; `mailer.py` их отправляет. ФИО и названия компаний в письма не попадают.

### Один раз

1. В `local.env` допишите (по образцу в `local.env.example`): `CHECKO_API_KEY` (ключ API Checko из личного кабинета: без него выгрузка на `/leads` не работает), `SURVEY_LINK` (ссылка на **форму** опроса `docs.google.com/forms/…/viewform`, не на таблицу с ответами; откройте её в окне без входа в Google, форма должна открываться), `MAIL_SIGNATURE` (подпись под письмом: нужна, только если в шаблонах агентов есть `{{подпись}}`; нет такой подстановки, ничего вписывать не надо), `OUTREACH_LETTERS` и `OUTREACH_SEGMENT` (пути к файлам писем и сегмента в папке агентов). Пока подписи или ссылки нет, письма не собираются. Лимит писем в сутки задаётся не здесь, а на странице `/mail` сайта.
2. В папке данных создайте пустой `stoplist.txt`. В нём адреса (`name@mail.ru`) или целые домены (`@registrar.ru`): по одному в строке или несколько в строке через запятую, точку с запятой или пробел. Всё после `#` игнорируется.

### Несколько ящиков и прогрев

Можно подключить до пяти ящиков mail.ru. Адрес и пароль каждого лежат в `local.env`: первый ящик в строках `MAILRU_USER` и `MAILRU_APP_PASSWORD`, второй в `MAILRU_USER_2` и `MAILRU_APP_PASSWORD_2`, третий `_3` и так далее (имя отправителя второго по умолчанию как у первого, свое: `MAIL_FROM_NAME_2`). Вписаны должны быть оба значения ящика, иначе отправка не запустится и скажет, чего не хватает. Пароль в `local.env` вписывает владелец сам: в чат и в репозиторий его присылать не нужно. После правки `local.env` перезапустите сайт (красный квадрат в PyCharm и снова `run_local`). Проверка нового ящика: страница `/mail`, блок «Письмо», выбор «С какого ящика отправить пробное письмо».

**Копия в «Отправленные».** После каждого письма, которое принял mail.ru, программа кладёт его копию в папку «Отправленные» того же ящика (по IMAP, `imap.mail.ru:993`, логин и пароль те же, что для SMTP), и вы видите в почте, что ушло; для пароля внешнего приложения должен быть включён доступ по IMAP. Настройки в `local.env`: `SAVE_SENT_COPY` (по умолчанию 1; 0 выключает копии), `MAILRU_IMAP_HOST` (`imap.mail.ru`), `MAILRU_IMAP_PORT` (`993`). Сбой копии отправку не останавливает: письмо не повторяется, журнал и код выхода не меняются, в `mailer.log` появляется строка «копия в Отправленные не сохранена (причина)» (при успехе «копия в Отправленные: ок»). Три сбоя подряд, неверный логин или отсутствие папки «Отправленные» отключают копии до конца запуска (новую папку программа не создаёт). Сколько копий не сохранилось за последний запуск, показывает `python mailer.py "<таблица или папка данных>" --status`; пробное письмо на `/mail` пишет «копия в Отправленные: сохранена» или «не сохранена (причина)».

**Как идёт отправка.** Один фоновый процесс, письма уходят по очереди с выбранных ящиков (1, 2, 1, 2…); между любыми двумя письмами случайная пауза от 30 до 75 секунд (ключи `--pause` и `--jitter`: пауза от `--pause` до `--pause * (1 + --jitter)`, по умолчанию 30 и 1,5). Два ящика никогда не пишут одновременно: между двумя письмами с одного ящика проходит не меньше одной паузы (при двух ящиках обычно две). Одному адресату письмо уходит с одного ящика один раз, а дожим и закрывающее письмо идут с того же ящика, что и первое (если этого ящика нет среди выбранных или на сегодня у него нет квоты, письмо ждёт до следующего раза).

**Прогрев.** У каждого ящика своя дата первого письма. В этот день с него можно отправить 7 писем, в каждый следующий день на 3 больше (7, 10, 13, 16, …), но не больше жёсткого предела недели прогрева: дни 1-7 не больше 15 (7, 10, 13, 15, 15, 15, 15), дни 8-14 не больше 30, с 15-го дня не больше 40. Предел недели зашит в программу (`mailing/mailboxes.py`, константы `WARMUP_WEEK_CAPS` и `WARMUP_CAP_LATER`) и от настройки на `/mail` не зависит. Потолок «Лимит отправки» на странице `/mail` (по умолчанию 40, от 1 до 50) может только понизить его, повысить не может. Сутки считаются календарные, по Москве. Кроме квоты дня действует и потолок за последние 24 часа. Дату первого письма проще всего записать один раз в `local.env` рядом с ящиками: `MAIL_FIRST_MESSAGE=2026-10-10` для первого ящика и `MAIL_FIRST_MESSAGE_2=2026-10-12` для второго (формат ГГГГ-ММ-ДД; испорченная дата не даст запустить отправку и скажет, какая строка). Не записана: дата берётся по журналу отправки (самое раннее письмо с этого ящика; старые записи журнала до подключения второго ящика считаются письмами первого). Если с ящика ещё ничего не отправляли, день 1 наступает с первым письмом. Свою дату можно вписать на странице `/mail`, блок «Ящики и прогрев» (она главнее `local.env`; кнопка «Сбросить» убирает дату, вписанную на странице, и остаётся дата из `local.env` или журнала). Если число писем в партии больше суммы квот, сегодня уйдёт сколько разрешено, остальные уйдут в следующие дни той же кнопкой или командой.

**Со скольки почт отправлять.** На странице `/leads`, блок «Отправка писем»: поле «Со скольки почт отправить» (по умолчанию все подключённые, сейчас 2) и список «Или только с одной почты». В окне проверки видно, сколько писем с какого ящика уйдёт сегодня. В командной строке то же: `python mailer.py "<таблица>" --send --mailboxes 1` (с первых N ящиков) или `--mailbox 2` (только с ящика 2; `1,2` с обоих); без этих ключей письма идут со всех подключённых ящиков.

**Квоты без таблицы.** `python mailer.py "E:\Codes\outreach-data" --status` печатает по строке на каждый ящик: день прогрева, неделя и действующий жёсткий предел недели, сколько можно отправить сегодня, сколько уже ушло, сколько осталось, дату первого письма (адреса скрыты: `n***@mail.ru`). Тот же `--status` с таблицей `letters_1.csv` показывает и ход партии. Проверка без отправки (`mailer.py "<таблица>"` без `--send`) показывает, с какого ящика какое письмо уйдёт.

### Каждая партия: кнопкой на сайте

1. На странице `/leads` вставьте текст Checko, укажите дату и нажмите «Запустить». Таблица `leads_<дата>.csv` сама сохраняется в папку данных: скачивать и переносить её не нужно. Таблица на странице показывается только за ту дату, что стоит в поле «Дата регистрации»: откройте страницу через неделю, и она пустая, пока вы не введёте дату; введите прошлую дату, и увидите сохранённую выгрузку за этот день с отметками, кому что ушло (скачивание и «Отправить» тоже работают с этой датой). Колонки «да» и «нет» в файле `leads_<дата>.csv` обновляются, когда вы открываете эту дату на странице или скачиваете таблицу.
   **Карта ОКВЭД (агент решает, к какой группе относится каждый вид деятельности).** Таблица классов в файле сегмента грубая: она смотрит только на первые два знака кода. Поэтому агент по смыслу решает судьбу каждого кода отдельно (в какую группу, или «не писать»), а программа только применяет его решения. Порядок: (а) на странице `/leads` или командой `compose.py` в окне проверки появляется строка «ОКВЭД без решения агента: кодов N»; рядом с таблицей в папке данных лежит файл `okved_to_classify.md` (только коды и названия видов деятельности, ни адресов, ни названий компаний); (б) передайте этот файл агенту: он вернёт `okved-map.md`; положите его в папку `01-Segment/output` рядом с файлом сегмента (больше ничего вписывать не надо: программа находит его сама; другой путь: `OUTREACH_OKVED_MAP` в `local.env` или `--okved-map`); (в) проверьте окно ещё раз: строка про коды без решения исчезнет, а решения агента главнее таблицы классов. Решённые коды копятся в карте и повторно не запрашиваются. Не нашли файла карты: всё идёт по таблице классов, как раньше. Группа, у которой в таблице сегмента нет списка классов (например, «Интернет-торговля»), получает компании только по карте.

   **Форма организации (ООО, МБУ, ПК, …).** Программа берёт её из начала названия компании (само название никуда не передаётся). Пока агент не решил иначе, письма получают только ООО (так записано в сегменте: «только ООО»). Остальные формы пропускаются, а в окне проверки видно, какие именно, и они попадают в тот же файл `okved_to_classify.md` в раздел «Формы организаций без решения». Решение агент записывает в `okved-map.md` отдельным разделом `## Формы` (таблица «Форма | Решение | Почему», решение «писать» или «не писать»). Если у названия нет известной формы, программа пишет «не определена по названию» и тоже не пишет. Выгрузка без колонки «Название» не проверяется.

   **Фильтр форм на странице `/leads`.** Организации форм «не писать» из `okved-map.md` (раздел `## Формы`: ТСН, МБУ, ПК…) страница не запрашивает в API Checko, а помечает в журнале и в сводке рядом со счётчиками (`form_skipped`); путь к файлу задаёт `OUTREACH_OKVED_MAP` в `local.env` (для этой страницы обязателен), файл читается при каждой выгрузке, а если ключа или файла нет, вверху страницы стоит предупреждение «правила форм не найдены, фильтр отключён».

   **Свой шаблон письма для запасной группы.** Запасную группу (неизвестный ОКВЭД) и группы без своего блока боли можно писать отдельным шаблоном целиком, а не общим с блоком боли. В файле писем это разделы с заголовками «Письмо 1. Запасной шаблон», «Дожим. Запасной шаблон», «Закрывающее письмо. Запасной шаблон» (слово «Запасной» в заголовке, внутри один блок из тройных кавычек ```). Нет такого раздела: берётся общий шаблон с запасным блоком боли, как раньше. Если у этапа есть свой запасной шаблон, запасной блок боли для этого этапа не нужен.
2. Ниже таблицы блок «Отправка писем»: впишите, сколько писем отправить и со скольки почт (по умолчанию со всех подключённых; можно выбрать одну конкретную), нажмите «Отправить». Откроется окно проверки: сколько писем соберётся, по каким группам, сколько адресов пропущено и почему, с какого ящика сколько уйдёт сегодня (квота прогрева) и пример письма (без адреса и ФИО). Нажмите «Отправить N писем» в окне, и отправка пойдёт в фоне с паузой 30–75 секунд между письмами; страницу можно закрыть. Дневной лимит, журнал, стоп-лист и «одна отправка на папку» работают те же, что в командной строке.
3. В таблице три колонки «Первое письмо», «Дожим», «Закрывающее» со значениями «да» или «нет» (они же есть в скачанном файле Excel и в `leads_<дата>.csv`) и колонка «Письмо» с временем отправки. У кого письмо уже ушло, у того строка залита полупрозрачным жёлтым до колонки последнего ушедшего письма: ушло только первое, заливка кончается на «Первое письмо»; был дожим, на «Дожим»; закрывающее, на «Закрывающее». Колонки писем, которых ещё не было, не заливаются. «Адрес не принят» красным. Тем, кому письмо уже отправлено, оно повторно не уходит. Если письма для какой-то группы агенты ещё не написали, их по умолчанию не собирают; галочка под числом писем разрешает отправить таким компаниям запасной вариант текста.
4. Дожим и закрывающее письмо, стоп-лист, ответы опроса: командной строкой, пункты 5–7 ниже.

### Каждая партия: командной строкой

Команды вводите на вкладке **Terminal** в PyCharm (в начале строки `(venv)`). Те же шаги, что делает кнопка на сайте.

1. **Таблица.** Возьмите `leads_<дата>.csv` из папки данных (на странице `/leads` её же можно скачать). В ней должны быть колонки «ОКВЭД (код)» и «Источник почты»: старые выгрузки без них не подойдут, выгрузите заново. Письма пойдут только на адреса с источником «ЕГРЮЛ» (адреса из контактов Checko пропускаются).
2. **Сборка и просмотр.**
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --limit 150 --preview
   ```
   Вместо таблицы можно указать папку данных: `python compose.py "E:\Codes\outreach-data" --limit 15 --preview`. Тогда берутся все сохранённые таблицы `leads_<дата>.csv` (от старых дат к новым; `--date 2026-10-09` оставляет одну), а письма собираются тем из них, кому ещё ничего не отправляли. Так отправляют по уже собранной базе: вставлять текст Checko и запускать выгрузку заново не нужно (сайт при этом может работать, как обычно). Программа напишет, сколько писем собрано, по каким группам, сколько адресов пропущено и почему, и покажет по одному письму на группу (без адресов). Группы, для которых агенты ещё не написали блок боли, не собираются: программа об этом скажет. Тему можно выбрать ключом `--subject 2`. В папке данных появится `letters_1.csv`.
3. **Пробные письма себе** (проверка доставки на своих ящиках).
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --test-to ваш@mail.ru,ваш@gmail.com
   python mailer.py "E:\Codes\outreach-data\letters_test.csv" --send
   ```
   Каждый адрес получит письмо одной из групп. Посмотрите в ящике, как оно выглядит, не в спаме ли, открывается ли ссылка на опрос без входа в Google. Повторить пробу тем же адресам можно после удаления `letters_test.sent.json`.
4. **Первая партия.**
   ```
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --mask-addresses
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --send --limit 5
   ```
   Первая команда только проверяет. Между письмами пауза от 30 до 75 секунд (случайная). За сутки с одного почтового ящика не уходит больше писем, чем задано в блоке «Лимит отправки» на странице `/mail` сайта (запустите `run_local`; по умолчанию 40), а новому ящику прогрев разрешает ещё меньше (7 писем в первый день, потом на 3 больше; см. «Несколько ящиков и прогрев»). Новое значение лимита действует со следующего запуска отправки. Остальные письма партии уйдут при следующем запуске, когда у ящиков появится квота. В каждое письмо добавляется заголовок List-Unsubscribe.

   **Отправка в фоне.** С ключом `--background` программа запускает отправку отдельным процессом и сразу возвращает управление, ждать окончания не нужно:
   ```
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --send --limit 40 --background
   python mailer.py "E:\Codes\outreach-data\letters_1.csv" --status
   ```
   Вторая команда показывает, сколько отправлено и осталось, идёт ли отправка и последние строки журнала `mailer.log` (адреса в нём скрыты: `n***@mail.ru`). В одной папке одновременно идёт только одна отправка (файл `mailer.lock`): вторую программа не запустит. Продолжить партию на следующий день можно той же командой.
5. **Ящик ответов и отписки.** Читайте ящик каждый день. Отказ, просьба удалить данные, жалоба: адрес сразу в `stoplist.txt` (программа пропустит его при следующем запуске), партию на паузу, дальше решаете вы. **Возвратные письма** («Письмо не может быть доставлено», Mail Delivery) программа не читает: сервер mail.ru принимает письмо и только потом возвращает отказ получателя, поэтому в журнале и в таблице такой адрес остаётся «отправлено». Адреса из возвратных писем вносите в `stoplist.txt` сами, иначе дожим уйдёт и им. **Пауза** значит: не запускать новую отправку. Письма сами не уходят никогда: только когда вы нажимаете «Отправить» на сайте или дирижёр запускает `mailer.py`. Идёт ли отправка сейчас, видно на странице `/leads` (надпись «Идёт отправка в фоне») или по `python mailer.py "<таблица>" --status`; кнопки остановки у фоновой отправки нет, при необходимости её завершают в диспетчере задач (процесс из строки «Отправка уже идёт (процесс N)»). Скажите дирижёру «партия на паузе», чтобы он ничего не отправлял и записал это в `batches.md`.
6. **Дожим (через 3 рабочих дня) и закрывающее (через 7 дней).** Раз в день скачайте ответы опроса из Google Таблицы файлом CSV и положите в папку данных как `responses.csv` (программа ищет в нём все адреса почты). Затем:
   ```
   python compose.py "E:\Codes\outreach-data\leads_2026-10-09.csv" --stage 2 --preview
   python mailer.py "E:\Codes\outreach-data\letters_2.csv" --send --limit 5
   ```
   Для этапа 2 берутся адреса, которым первое письмо отправлено три рабочих дня назад и раньше; для этапа 3 (`--stage 3`) те, кому ушёл дожим и с первого письма прошла неделя. Те, кто есть в `responses.csv` или в стоп-листе, не получают ничего. Тема и группа берутся из журнала отправки, письмо всегда на тот же адрес и с той же темой. Больше трёх писем на адрес не уйдёт. Кто заполнил опрос с другого адреса или указал только телефон или Telegram, получит дожим: этот риск принят.
7. **Итоги партии** в `batches.md`: сколько отправлено (число в журнале `letters_1.sent.json`, строки со статусом `sent`), недоставлено, ответов, отписок.

### Если программа остановилась

`mailer.py` печатает причину; код выхода:

| Код | Что случилось | Что делать |
|---|---|---|
| 0 | Готово | Посмотреть, сколько отправлено |
| 1 | Ошибка в таблице или не заданы `MAILRU_USER` / `MAILRU_APP_PASSWORD` | Исправить таблицу или `local.env` |
| 2 | mail.ru не принял логин или пароль | Нужен «пароль для внешних приложений», а не обычный. Не повторять |
| 3 | mail.ru отказал или ограничил отправку (например `451 Ratelimit exceeded`) | Остановиться. Продолжать не раньше чем через несколько часов, партию уменьшить |
| 5 | Несколько временных отказов подряд | Остановиться, повторить позже |

Повторный запуск с той же таблицей безопасен: кому письмо уже ушло, тому оно повторно не отправляется. Журналы `letters_*.sent.json` не удаляйте: по ним считаются дожим, закрывающее и дневной лимит. Нельзя: уменьшать `--pause` ниже 30 секунд, перезапускать сразу после кода 2, 3 или 5, пробовать тем же письмом с другого ящика (если один из ящиков получил отказ или лимит, второй не подхватывает его письмо), обходить квоту прогрева ключами или правкой журнала. В сообщениях программы ящик назван номером («ящик 2»): ошибка входа, лимит или отказ относятся к нему. Если сервер ограничил отправку, это сигнал сбавить темп, а не обойти.

Страница `/mail` остаётся проверкой соединения с mail.ru (с любого подключённого ящика) и местом, где задаются лимит в сутки и даты первого письма ящиков: пример письма на ней устроен иначе, чем письма рассылки.

## Если что-то не так

- **С включённым VPN Checko не отвечает, а без VPN работает.** Checko (как многие российские сервисы) закрывает соединения с зарубежных адресов, а при VPN запросы идут с адреса VPN: ни Python, ни `curl` тут не виноваты. Программа обходит это сама: если обычный запрос оборвался, она отправляет запросы к Checko напрямую, через настоящую сетевую карту (Ethernet или Wi-Fi), мимо VPN; остальной интернет по-прежнему идёт через VPN. Права администратора не нужны, работает только в Windows. Не помогает, если в VPN включена блокировка трафика вне VPN («kill switch»): выключите её или добавьте в исключения VPN (раздельное туннелирование) программу, которой запущен сайт. Нужны оба пути (python.exe из `venv` запускает базовый), `check_checko.py` печатает их в конце, обычно это `E:\Codes\coldoutreach\vikmax\1venv\Scripts\python.exe` и python.exe базовой установки Python. Либо исключите адреса `api.checko.ru` и `checko.ru`. Если в строке «Запрос к API (в обход VPN…)» стоит «сертификат не принят», программа сама пробует проверить сертификат средствами Windows (как браузер; для этого нужен пакет `truststore`: `pip install -r requirements.txt`), а `check_checko.py` в блоке «Сертификат, который присылает Checko» покажет, кем выдан сертификат, и что делать (например, для сертификата российского удостоверяющего центра: скачать корневой сертификат и вписать путь к нему в `local.env` строкой `CHECKO_CA_FILE=…`). Проверить, обходит ли программа VPN, можно запуском `check_checko.py` при включённом VPN: строка «Запрос к API (в обход VPN…)» должна быть «ок», а в списке «Сетевые карты с выходом в интернет» одна из карт помечена «через неё идёт обход VPN» (если там пусто или написана причина сбоя, значит, мимо VPN из программы выйти нельзя: используйте исключения в самом VPN). Письма (`mailer.py`) идут на `smtp.mail.ru` тоже с адреса VPN, а mail.ru смотрит, откуда входят в ящик: если письма не уходят или ящик просит подтвердить вход, для рассылки исключите python.exe из VPN или выключайте VPN.
- **На странице `/leads` в журнале «защищённое соединение с api.checko.ru оборвано (SSL)», «прокси не пропустил запрос» или «нет соединения»,** а выгрузка пишет «Данные не получены». Это не пароль и не ключ (с неверным ключом пришёл бы «HTTP 401» или «403»): компьютер не может установить соединение с Checko. Программа сама пробует обойти (без системного прокси, потом с TLS 1.2, потом через системную программу curl: в Windows 10 она встроена и шифрует средствами самой Windows, а не Python), но если и это не помогло, запустите `check_checko.py` (правой кнопкой на файле → *Run 'check_checko'*): по шагам проверит адрес (и сверит его с публичным DNS), соединение, шифрование, запрос из Python и через curl, обычные сайты и сам ключ (один настоящий запрос из 100 бесплатных в сутки) и простыми словами напишет, где обрыв. В тексте «No such file or directory» среди ошибок файл ни при чём: так Python иногда сообщает, что сервер закрыл соединение посреди установки шифрования. Чаще всего мешает VPN или прокси с не российским адресом либо антивирус с проверкой защищённых соединений (Kaspersky, ESET, Dr.Web): отключите VPN, а в антивирусе отключите проверку HTTPS или добавьте `api.checko.ru` в исключения.

- **Какая версия сейчас стоит в папке (после обновления, перед отправкой, если дирижёр сомневается)** — `python check_version.py` (или правый клик на файле → *Run 'check_version'*). Он только читает: показывает ветку и коммит, чистая ли папка, не отстаёт ли она от origin, есть ли ключи `--mailboxes`, `--mailbox`, `--jitter`, прогрев с недельными пределами и дата первого письма в `local.env`. Итог «ВЕРСИЯ ОК» или список того, чего не хватает (тогда отправлять нельзя). Адресов и паролей в выводе нет.
- **Нужно проверить тесты или что-то упало после обновления** — правый клик на `check_tests.py` → *Run 'check_tests'*: через минуту в окне Run будет итог и список упавших тестов с последней строкой ошибки (пароли, ключи и адреса почты скрыты, содержимое `local.env` и `settings.json` не читается). Пришлите этот вывод. В PowerShell `python -m unittest` ломает русские буквы, поэтому лучше так.

- **«Не заполнено: …»** — впишите значения в `local.env`, сохраните (Ctrl+S), запустите снова.
- **«No module named requests»** (или другой модуль) — пакеты не установились в то окружение, которым запускается проект: повторите шаг 4 и проверьте, что в правом нижнем углу выбран тот же интерпретатор, что в терминале.
- **«Соединение с smtp.mail.ru:465 оборвалось при установке защищённого соединения» (в тексте `EOF occurred in violation of protocol`)** — это не пароль и не сертификат: соединение до сервера доходит, но шифрование обрывают. Чаще всего мешает VPN (mail.ru не любит входы с адресов VPN), прокси или антивирус с проверкой HTTPS (Kaspersky, ESET, Dr.Web), реже провайдер. Запустите `check_cert.py` (правой кнопкой → *Run 'check_cert'*): он проверит порты 465 и 587 и в конце простыми словами скажет, что делать. Порядок: выключите VPN на минуту и запустите снова; если без VPN работает, исключите из VPN программу `python.exe`, которой запущен сайт; на минуту отключите в антивирусе проверку защищённых соединений. Если 465 не работает, а 587 работает, впишите в `local.env` строку `MAILRU_PORT=587`, сохраните (Ctrl+S) и перезапустите сайт: пробное письмо и рассылка (`mailer.py`) пойдут через 587. Письма с одного ящика на другой «в обход» не пробуют: ошибка соединения не зависит от ящика.
- **«Не удалось проверить защищённое соединение… (SSLCertVerificationError)»** — Python не смог проверить сертификат `smtp.mail.ru`. Это происходит до ввода пароля, к паролю отношения не имеет. Сначала обновите проект (**Git → Update Project**) и запустите снова: программа доверяет и хранилищу Windows, и стандартному набору `certifi`. Если ошибка осталась, запустите `check_cert.py` (правой кнопкой → *Run 'check_cert'*) и пришлите его вывод: там видно, кем выдан сертификат. Отключать проверку сертификатов нельзя: тогда пароль могут перехватить. Если понадобится добавить корневой сертификат вручную, впишите в `local.env` строку `MAILRU_CA_FILE=путь\к\файлу.pem`.
- **«mail.ru не принял логин или пароль»** — нужен именно пароль для внешних приложений, а `MAILRU_USER` должен быть полным адресом.
- **«Порт занят»** — в *Run → Edit Configurations… → Parameters* впишите `--port 8001`.
- **Другая ошибка в красной строке под кнопкой** — пришлите её текст.
