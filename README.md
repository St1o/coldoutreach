# Выписка из ЕГРЮЛ / ЕГРИП по ИНН

Простой сайт: вводите ИНН, нажимаете «Найти», затем «Получить выписку» и скачиваете PDF с egrul.nalog.ru.

## Запуск

```
pip install -r requirements.txt
python app.py
```

Откройте http://127.0.0.1:8000. Другой порт: `python app.py --port 8080`.

По умолчанию сайт доступен только с вашего компьютера. Чтобы открыть его всем, см. раздел «Публичный сайт».

## Почему не GitHub Pages

GitHub Pages отдаёт только статичные файлы. Страница на `github.io` не может обратиться к egrul.nalog.ru из браузера (запрет CORS), поэтому нужен серверный запрос. Код лежит на GitHub, а запускается там, где есть Python: на вашем компьютере или на хостинге с поддержкой Python (сервер читает переменные `HOST` и `PORT`).

## Новые компании: название, ФИО директора, почта, основной ОКВЭД

Программа берёт организации, зарегистрированные в нужный день, со страницы [checko.ru/company/updates](https://checko.ru/company/updates) («Новые организации»), скачивает по каждой выписку из ЕГРЮЛ, читает из неё ФИО руководителя и почту и собирает таблицу. **В таблицу попадают только организации с почтой.** Для каждой берётся основной ОКВЭД (код и название): по нему рассылочные агенты выбирают, как обращаться к компании.

```
python leads.py                                  # сегодняшние регистрации (по Москве)
python leads.py --date 2026-10-09                # за конкретный день
python leads.py --date 2026-10-09 --limit 20     # проверить только 20 организаций за запуск
```

Результат: `leads_<дата>.csv` с колонками «Название», «ФИО директора», «Почта», «ОКВЭД (код)», «ОКВЭД (название)» (открывается в Excel) и служебный `leads_<дата>.state.json` рядом.

- Файлы обновляются после каждой организации. Если ФНС попросит капчу, программа остановится, а готовое сохранится. Повторный запуск с той же датой продолжит с того же места.
- Организации без почты второй раз не проверяются. Ошибки и организации, которых ещё нет в ЕГРЮЛ (регистрация только что прошла), проверяются при следующем запуске.
- На проверку одной организации уходит несколько секунд (с паузой между организациями), поэтому полный день занимает десятки минут. Для первой пробы используйте `--limit 5`.
- В журнал программа выводит только ИНН и статус, без ФИО и почты.
- Организации, проверенные до появления колонки ОКВЭД, при следующем запуске с той же датой один раз дозаполняются.
- ОКВЭД из API Checko берётся из поля `ОКВЭД` (запасной вариант: исходные данные ЕГРЮЛ). Из выписки ФНС он читается по разделу «Сведения об основном виде деятельности»; эту раскладку на настоящих выписках ещё не проверяли. Если колонка у каких-то организаций пустая, пришлите такую выписку, и разбор поправят.

То же можно запустить на GitHub: **Actions → «Новые компании - ФИО и почта» → Run workflow** (готовый `leads.csv` будет в разделе Artifacts, прерванный запуск начинается заново). Но при проверке 09.10.2026 Checko ответил серверам GitHub кодом 429 и страницу не отдал, поэтому надёжнее запускать на своём компьютере.

### Запуск на сервере (Render), без своего компьютера

На сайте есть закрытая страница `/leads` (по паролю): в ней можно запустить выгрузку и скачать таблицу.

1. На Render: сервис → **Environment** → **Add Environment Variable**: имя `LEADS_TOKEN`, значение — ваш пароль (не короче 12 знаков, латиница и цифры). Без этой переменной страница отключена и отвечает 404.
2. Дождитесь, пока сервис перезапустится (статус **Live**).
3. Откройте `https://имя-сервиса.onrender.com/leads`, введите пароль, дату (пусто — сегодня) и количество организаций (для пробы 5), нажмите «Запустить».
4. Пока идёт выгрузка, не закрывайте страницу: бесплатный сервис Render засыпает через 15 минут без запросов, а страница сама обращается к серверу каждые 3 секунды. Готовую таблицу скачайте кнопкой на той же странице; она хранится на сервере до его перезапуска.

Подбор пароля ограничен (5 неверных попыток в минуту с одного адреса). Одновременно идёт одна выгрузка.

Пароль можно не вводить каждый раз: страница запоминает его в вашем браузере (галочка «Запомнить пароль», кнопка «Забыть»). Вписывать пароль в код страницы нельзя: она открыта всем, и пароль увидел бы любой посетитель. Если перезагрузить страницу, она сама покажет ход или результат последней выгрузки.

**Быстрый способ без капчи: API Checko.** На странице `/leads` есть выбор источника. «API Checko» берёт ФИО руководителя и почту из официального API (`api.checko.ru`) по ключу: одна организация за долю секунды, без капчи (по документации Checko, 32 запроса в секунду, бесплатно 100 запросов в сутки, дальше по тарифу). Как включить: зарегистрируйтесь на checko.ru, возьмите API-ключ в личном кабинете и на Render добавьте переменную окружения `CHECKO_API_KEY` с этим ключом (ключ нигде больше не вводите и никому не присылайте). Если ключ задан, источник «Автоматически» выберет API.
- Почта берётся сначала из исходных данных ЕГРЮЛ (та же, что в выписке), а если её там нет, из контактов Checko. Такие контакты Checko берёт «из открытых источников», они могут быть неполными или устаревшими, поэтому в журнале такие строки помечены «почта из контактов Checko, не из ЕГРЮЛ». Не нужна такая почта — выберите «Выписки ФНС».
- Список ИНН за день по-прежнему берётся с checko.ru/company/updates (вставкой текста страниц, пока Checko не отдаёт эти страницы серверу).
- При исчерпанном лимите или балансе выгрузка останавливается с понятным сообщением, готовая часть сохраняется.

**Если ФНС просит капчу.** Это защита сайта egrul.nalog.ru от частых запросов. Программа её не обходит и не проходит: ни распознавания, ни смены адресов в ней нет и не будет. Вместо этого на странице `/leads` выгрузка при капче **ждёт 10 минут и продолжает с той же организации** (до 6 раз подряд, потом останавливается), а кнопка «Остановить» прерывает её в любой момент; готовая часть таблицы сохраняется. В консольной версии то же включается ключом `--captcha-wait 10` (минут). Чтобы капча появлялась реже, поставьте паузу побольше (поле «Пауза, с», по умолчанию 6) и берите организаций поменьше за запуск. Страницу не закрывайте, пока идёт выгрузка, и скачайте таблицу до закрытия: бесплатный сервис Render теряет файлы, когда засыпает или перезапускается.

Данные большими объёмами ФНС отдаёт и официально, без капчи: открытые данные ЕГРЮЛ на nalog.gov.ru (большие файлы; наличие адреса почты в них нужно проверить) и платные API (у Checko, у API-ФНС).

**Если Checko не отдаёт страницы серверу.** Проверено 09.10.2026: и серверам GitHub, и серверу Render Checko отвечает кодом 429. В этом случае на странице `/leads` раскройте блок «Checko не пускает сервер? Вставьте текст страниц сами»: откройте `checko.ru/company/updates` в своём браузере, нажмите Ctrl+A, Ctrl+C и вставьте текст в поле (если нужный день занимает несколько страниц, откройте следующие и добавьте их текст туда же). Сервер возьмёт из текста организации за выбранный день, а выписки скачает сам.

Что надо знать:

- Страница Checko читается по тому, как она выглядит сейчас: «Дата регистрации … ОГРН … ИНН …». Если сайт изменит вид, поменяйте `checko_updates.py`. На странице доступны только последние 2000 организаций, поэтому старые даты могут оказаться недоступны.
- Checko и ФНС могут потребовать капчу или закрыть доступ при частых запросах, программа это не обходит. У Checko есть и платный API (checko.ru/integration/api), который стабильнее разбора страницы. Условия использования сайта проверьте сами.
- Рассылки по собранным адресам регулируются законом (в том числе о рекламе и о персональных данных). Для публичного репозитория учтите, что артефакты Actions доступны любому, кто вошёл в GitHub: храните список в приватном репозитории.

## Рассылка из вашей почты (Cowork + `send_mail.py`)

Как это работает целиком:

```
leads.py / страница /leads  ->  leads_<дата>.csv  (название, директор, почта, ОКВЭД)
                                      |
                       Cowork: по строке читает компанию, по ОКВЭД выбирает агента,
                       готовит письмо и добавляет строку в outbox_<дата>.csv
                                      |
        send_mail.py: отправляет из вашего ящика с паузой, лимитом и журналом
```

Cowork отвечает за то, что написать, а `send_mail.py` - за то, как отправить. Лимиты и защиту от повторов держит программа, а не агент: агент может ошибиться и написать одному адресу дважды, программа - нет.

**1. Файл с письмами.** Cowork пишет `outbox_<дата>.csv`: первая строка «Почта;Тема;Текст», дальше по строке на письмо (разделитель `;` или `,`, текст может быть в несколько строк). Другие колонки (название, ОКВЭД, имя агента) не мешают. Текст - обычный, без HTML.

**2. Настройки ящика** (переменные окружения на вашем компьютере; в файлы и в журнал пароль не попадает):

| Ящик | `SMTP_HOST` | `SMTP_PORT` |
|---|---|---|
| Gmail | `smtp.gmail.com` | `587` |
| Яндекс | `smtp.yandex.ru` | `465` |
| Mail.ru | `smtp.mail.ru` | `465` |
| Outlook | `smtp-mail.outlook.com` | `587` |

Дальше `SMTP_USER` (адрес ящика) и `SMTP_PASSWORD`. Нужен **пароль приложения**, а не обычный пароль от почты (Gmail: «Управление аккаунтом» -> «Безопасность» -> «Пароли приложений», нужна двухфакторная защита; в Яндексе и Mail.ru пароль приложения создаётся в настройках безопасности). Необязательно: `MAIL_FROM` (если адрес отправителя отличается от логина) и `MAIL_FROM_NAME` (имя, которое увидит получатель).

**3. Запуск.**

```
python send_mail.py outbox_2026-10-09.csv                   # пробный: ничего не уходит, первые письма показаны целиком
python send_mail.py outbox_2026-10-09.csv --send --limit 3  # первые 3 настоящих (поставьте первой строкой свой адрес)
python send_mail.py outbox_2026-10-09.csv --send            # дальше: до 50 писем за 24 часа, пауза 45 с
python send_mail.py outbox_2026-10-09.csv --send --daily-limit 200
```

- **Без `--send` письма не отправляются.** Пробный запуск не требует пароля.
- **Один адрес - одно письмо.** Журнал `sent_mail.json` помнит всех, кому писали, включая другие outbox-файлы. Если связь оборвалась в момент отправки и неизвестно, дошло ли письмо, адрес получает статус `sending` и сам не повторяется: проверьте папку «Отправленные»; `--retry-unknown` отправит такие письма заново. Журнал не удаляйте.
- **Лимит.** По умолчанию не больше 50 писем за любые 24 часа. Для 200 в день поставьте `--daily-limit 200`, но не в первый же день: новому или давно молчавшему ящику нужно набирать объём постепенно (например, 20-30, затем 50, 100, 200 по дням), иначе почтовик заблокирует ящик за спам. 200 писем с паузой 45 с идут около 2,5 часов: не закрывайте окно. Остальное, что не влезло в лимит, уйдёт при следующем запуске.
- **Остановка при отказе сервера** (лимит ящика, ошибка входа, обрыв): программа останавливается и пишет причину. Письмо, на которое пришёл отказ, считается неотправленным и уйдёт при следующем запуске. Пять отвергнутых адресов подряд тоже останавливают отправку.
- **Список отказов.** Тем, кто попросил не писать, добавьте адрес (или `@домен.ру`) строкой в `suppress.txt`: такие письма пропускаются. Ответы «отписаться» нужно разбирать самим.
- Две отправки одновременно не запустятся (файл `sent_mail.json.lock`). Если прошлая оборвалась аварийно и программа жалуется на блокировку, удалите этот файл.

**Не запускайте отправку в GitHub Actions и на публичном сервере:** там пришлось бы хранить пароль от вашей почты, а журналы и артефакты репозитория могут быть открыты. Запускайте на своём компьютере. Файлы `leads_*.csv`, `outbox*.csv`, `sent_mail.json`, `suppress.txt` внесены в `.gitignore`: в них персональные данные.

**Закон и репутация.** Рассылка рекламы по электронной почте без предварительного согласия получателя нарушает статью 18 закона «О рекламе»; письма без отказа от рассылки и без указания, кто пишет, быстрее попадают в спам. В тексте письма укажите, кто вы и как отказаться от писем, и учитывайте отказы.

## Публичный сайт

Чтобы любой посетитель мог открыть сайт по ссылке, нужен хостинг, где работает Python-программа (GitHub Pages для этого не подходит). Код хостинг берёт прямо из этого репозитория.

Пример, Render (бесплатный план: сайт засыпает через 15 минут без посетителей, первый заход после сна ждёт около минуты; для постоянной работы нужен платный план):

1. На render.com: New → Web Service → подключить репозиторий `St1o/coldoutreach` и нужную ветку.
2. Runtime: Python 3. Build Command: `pip install -r requirements.txt`. Start Command: `python app.py`. Health Check Path: `/healthz`.
3. Environment: `HOST=0.0.0.0` и `TRUSTED_PROXIES=1`.

Хостинг выдаст ссылку вида `https://имя.onrender.com`. Вместо шагов 2-3 можно использовать готовый `Dockerfile` (на хостингах с Docker он уже настроен).

После первого захода откройте логи сервиса: в строках `GET /api/search` должен быть ваш внешний адрес. Если там внутренний адрес хостинга (10.x, 172.x, 100.x), поставьте `TRUSTED_PROXIES=2`, иначе лимит запросов будет общим на всех посетителей.

Защита сайта ФНС от перегрузки (настраивается переменными окружения):

- `RATE_LIMIT` - запросов в минуту с одного адреса, по умолчанию 10;
- `MAX_QUEUE` - сколько запросов одновременно могут ждать реестр, по умолчанию 8; остальным сайт отвечает «много запросов, повторите»;
- к реестру идёт один запрос за раз с паузой 2 секунды, повторный ИНН в течение 5-10 минут отдаётся из памяти сервера;
- наш сервер не пишет ИНН в свой журнал (журналы самого хостинга могут сохранять адреса запросов целиком).

Что надо знать до публикации:

- Если сайт ФНС начнёт просить капчу для адреса хостинга, сайт будет показывать посетителям сообщение, пока ФНС не снимет ограничение. Капчу сервис не обходит.
- Массовое использование может противоречить условиям использования egrul.nalog.ru. Выписки по ИП содержат персональные данные: оцените, нужно ли ограничить круг посетителей.
- Адреса хостингов бывают заблокированы ФНС. Проверьте работу после запуска, а не по документации.

## Запуск на GitHub (без своего компьютера)

Во вкладке **Actions** выберите «Выписка по ИНН», нажмите **Run workflow**, введите один или несколько ИНН через пробел и запустите. Через минуту-две на странице запуска, внизу в разделе **Artifacts**, появится архив `vypiski` с PDF (хранится 7 дней, скачивать нужно, войдя в GitHub).

Это не сайт с формой, а штатная форма запуска GitHub Actions. Если сайт ФНС перестанет отвечать серверам GitHub или попросит капчу, запуск завершится ошибкой, а причина будет в логе шага «Скачать выписки».

## Из командной строки

```
python egrul_inn_search.py 7707083893                       # данные об организации
python egrul_inn_search.py 7707083893 500100732259 --pdf-dir выписки   # PDF по списку ИНН
```

Из кода (например, для ИНН из базы данных):

```python
from egrul_inn_search import EgrulClient

for res in EgrulClient().fetch_extracts(inns, "выписки"):
    print(res.inn, res.path or res.error)
```

## Устройство

- `egrul_inn_search.py` — клиент: проверка ИНН, поиск, запрос и скачивание выписки.
- `app.py` + `index.html` — сайт: страница и маленький сервер на стандартной библиотеке.
- `Dockerfile` — готовая сборка для хостинга с Docker.
- `checko_updates.py` — список новых организаций с Checko; `egrul_pdf.py` — ФИО, почта и основной ОКВЭД из выписки; `leads.py` — таблица из них.
- `send_mail.py` — отправка готовых писем из вашего ящика (SMTP) с паузой, лимитом и журналом.
- Запросы к реестру идут по одному, с паузой 2 секунды. Если сайт ФНС просит капчу, сервер сообщает об этом и ничего не обходит.

## Ограничения

- Клиент проверен на настоящем egrul.nalog.ru одним запуском в GitHub Actions (по ИНН организации выписка скачалась). Сайт может изменить адреса запросов и формат ответа. Если что-то перестанет работать, подробности ошибки печатаются в консоль сервера или в лог запуска.
- Скачанная выписка подписана электронной подписью ФНС и сохраняется без изменений.
- Массовые запросы к государственному сайту могут противоречить его условиям использования.
